## Canonical Definitions (mmr_client/proofs.rs)

```rust
// ============================================================================
// PROOF STRUCTURES - CANONICAL DEFINITIONS
// ============================================================================

/// Batch proof - proves multiple blocks are in MMR
#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct MMRBatchProof {
    pub genesis_hash: [u8; 32],
    pub batch_blocks: Vec<BlockData>,
    pub siblings: Vec<[u8; 32]>,
}

/// Range proof - proves contiguous range of blocks
#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct MMRRangeProof {
    pub genesis_hash: [u8; 32],
    pub target_block: BlockData,
    pub start_height: u32,
    pub end_height: u32,
    pub blocks: Vec<BlockData>,
    pub left_boundary: Vec<[u8; 32]>,
    pub right_boundary: Vec<[u8; 32]>,
}

/// Fork point proof - identifies chain divergence
#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct MMRForkProof {
    pub common_block: BlockData,
    pub chain_a_next: Option<BlockData>,
    pub chain_b_next: Option<BlockData>,
}

/// Chain weight proof - proves cumulative difficulty
#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct MMRChainWeightProof {
    pub target_block: BlockData,
    pub start_height: u32,
    pub end_height: u32,
    pub total_weight: u128,
    pub difficulties: Vec<u64>,
    pub range_proof: MMRRangeProof,
}

/// Chain summary - compact chain state for light clients
#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct MMRChainSummary {
    pub tip_block: BlockData,
    pub chain_weight: u128,
    pub recent_blocks_proof: MMRBatchProof,
}
```

## Verification Results (mmr_client/verification.rs)

**NEW IN v0.3.0:** Verification functions now return calculated peaks and leaf_count instead of trusting values from proofs.

### BatchProofVerificationResult

```rust
pub struct BatchProofVerificationResult {
    /// Whether the proof is valid
    pub valid: bool,
    
    /// Calculated MMR peaks (VERIFIED, not trusted from proof)
    /// These peaks are cryptographically verified to correctly hash to MMR roots
    pub peaks: Vec<[u8; 32]>,
    
    /// Leaf count derived from last block height
    /// Equals: last_block.height() + 1
    pub leaf_count: u32,
    
    /// Error message if verification failed
    pub error: Option<String>,
    
    /// Warnings (non-fatal issues)
    pub warnings: Vec<String>,
}
```

**Key Change:** The verifier CALCULATES peaks during verification using the climb-and-descend algorithm. This is more secure than transmitting peaks in the proof.

### RangeProofVerificationResult

```rust
pub struct RangeProofVerificationResult {
    pub valid: bool,
    pub peaks: Vec<[u8; 32]>,      // CALCULATED during verification
    pub leaf_count: u32,            // DERIVED from target_block.height()
    pub error: Option<String>,
    pub warnings: Vec<String>,
}
```

**Security Benefit:** Light clients don't trust transmitted peaks - they verify them cryptographically.

## Usage in FullBeaconChain/FullShardChain

```rust
// ============================================================================
// FULL NODE - FILLS IN CALLER FIELDS
// ============================================================================

// Example: generate_chain_summary
pub fn generate_chain_summary(&mut self, recent_count: usize) -> Result<MMRChainSummary, String> {
    let tip_block = BlockData::from(self.get_block(tip_height)?);
    
    let recent_blocks_proof = self.prove_batch_at_height(&heights, tip_height)?;
    
    Ok(MMRChainSummary {
        tip_block,          // ✓ Filled with actual block data
        chain_weight: self.chain_weight(),
        recent_blocks_proof, // ✓ Contains filled batch proof
    })
}

// Example: prove_batch_at_height
pub fn prove_batch_at_height(
    &self,
    batch_heights: &[u32],
    target_height: u32,
) -> Result<MMRBatchProof, String> {
    let genesis = self.get_block(0)?;
    
    let batch_blocks: Vec<BlockData> = batch_heights
        .iter()
        .map(|&h| BlockData::from(self.get_block(h)?))
        .collect::<Result<Vec<_>, _>>()?;
    
    let mmr_proof = self.mmr.prove_batch(batch_heights);
    
    Ok(MMRBatchProof {
        genesis_hash: genesis.hash(),  // ✓ Filled by full node
        batch_blocks,                   // ✓ Filled by full node
        siblings: mmr_proof.siblings,   // ✓ From MMR
    })
}

// Example: prove_range_at_height
pub fn prove_range_at_height(
    &mut self,
    start: u32,
    end: u32,
    target_height: u32,
) -> Result<MMRRangeProof, String> {
    let genesis = self.get_block(0)?;
    let target_block = self.get_block(target_height)?;
    
    let blocks: Vec<BlockData> = (start..=end)
        .map(|h| BlockData::from(self.get_block(h)?))
        .collect::<Result<Vec<_>, _>>()?;
    
    let mut mmr_range_proof = self.mmr.prove_range(start, end)?;
    
    // Fill in the fields that MMR couldn't know
    mmr_range_proof.genesis_hash = genesis.hash();
    mmr_range_proof.target_block = BlockData::from(target_block);
    mmr_range_proof.blocks = blocks;
    
    Ok(mmr_range_proof)
}
```

## Quick Verification Checklist

When generating proofs, verify:

- [ ] All proof types use `crate::mmr_client::proofs::*`
- [ ] Field order matches proofs.rs exactly
- [ ] Field types match proofs.rs exactly (u32, u64, u128, [u8; 32], Vec)
- [ ] Caller fills genesis_hash before returning
- [ ] Caller fills block data (batch_blocks, blocks, target_block)
- [ ] MMR generates boundaries (left_boundary, right_boundary) via climb_and_descend
- [ ] MMR generates siblings via climb_and_descend algorithm
- [ ] All BlockData uses proper `From<&BeaconBlock>` or `From<&Block>` conversions
- [ ] NO intermediate CompleteBatchBlock conversions (deprecated)
- [ ] Integration tests pass (full_node_integration_tests.rs)
- [ ] Verification returns calculated peaks (not trusted from proof)
- [ ] Chain weight proofs use ONLY Full blocks (ShardFull or Beacon)
- [ ] Light blocks rejected in chain weight proofs
- [ ] **NEW:** Chain weight V2 uses statistical sampling
- [ ] **NEW:** MMRLight stores calculated peaks from verification
- [ ] **NEW:** Storage uses ChainId namespacing (no collisions)

## Common Mistakes to Avoid

❌ **Don't reorder fields:**
```rust
// WRONG
MMRBatchProof {
    siblings,       // Wrong order!
    genesis_hash,
    batch_blocks,
}

// CORRECT
MMRBatchProof {
    genesis_hash,   // Match proofs.rs order
    batch_blocks,
    siblings,
}
```

❌ **Don't forget to fill caller fields:**
```rust
// WRONG - returns placeholder genesis_hash
return self.mmr.prove_batch(heights);

// CORRECT - fills genesis_hash
let mut proof = self.mmr.prove_batch(heights);
proof.genesis_hash = self.get_block(0)?.hash();
return proof;
```

❌ **Don't use deprecated types:**
```rust
// WRONG - deprecated
let batch = CompleteBatchBlock::from_beacon_block(&block);
let block_data = BlockData::from_complete_batch_block(&batch);

// CORRECT - direct conversion
let block_data = BlockData::from(&block);
```

## Summary

All proof signatures are carefully designed to:
1. **Match** between generation (full_mmr_core) and verification (mmr_client) ✓
2. **Serialize** identically with Serde (bincode/JSON) ✓
3. **Support** all three BlockData variants (Beacon, ShardFull, ShardLight) ✓
4. **Minimize** bandwidth while maintaining security ✓
5. **Allow** efficient verification without full chain data ✓
6. **Calculate** peaks during verification (NEW in v0.3.0) ✓
7. **Namespace** storage per chain (ChainId) to prevent collisions ✓
8. **Use** statistical sampling for chain weight (V2 proofs) ✓

### Three-Layer Architecture

The proof system works across three layers:

```
┌────────────────────────────────────────────┐
│  Layer 1: Proof Generation (Full Nodes)   │
│  - full_mmr_core.rs                        │
│  - Uses climb-and-descend algorithm        │
│  - Returns partial proofs                  │
└────────────────┬───────────────────────────┘
                 │
                 │ Fills block data
                 ▼
┌────────────────────────────────────────────┐
│  Layer 2: Proof Completion (Full Nodes)   │
│  - FullBeaconChain / FullShardChain        │
│  - Fills genesis_hash, target_block        │
│  - Fills batch_blocks, blocks vectors      │
│  - Uses BlockData::from(&block)            │
└────────────────┬───────────────────────────┘
                 │
                 │ Network transmission
                 ▼
┌────────────────────────────────────────────┐
│  Layer 3: Proof Verification (Light)      │
│  - mmr_client/verification.rs              │
│  - Verifies cryptographic proofs           │
│  - CALCULATES peaks (doesn't trust them)   │
│  - Updates MMRLight with verified peaks    │
└────────────────────────────────────────────┘
```

**All three layers must use identical type definitions!**

### Key Security Properties

1. **Trustless Peaks**: Light clients calculate peaks during verification rather than trusting transmitted values
2. **Bandwidth Optimized**: Statistical sampling reduces chain weight proofs from 22MB to ~400KB
3. **Type Safe**: BlockData enum enforces verification level (Full/Light) at compile time
4. **Deterministic**: Same proof inputs always produce same outputs
5. **Forward Compatible**: ChainId namespacing allows adding new chains without migration

### Recent Changes (v0.3.0)

✅ **Verification Returns Calculated Values**
   - `verify_batch_proof()` returns `BatchProofVerificationResult` with peaks
   - `verify_range_proof()` returns `RangeProofVerificationResult` with peaks
   - Light clients use these calculated peaks to update `MMRLight`

✅ **Statistical Chain Weight Proofs**
   - `MMRChainWeightProofV2` uses exponential sampling
   - Reduces proof size by ~98% (22MB → 400KB for 10,000 blocks)
   - Maintains security with statistical confidence >99.9999%

✅ **Storage Namespacing**
   - `ChainId` enum prevents beacon/shard collisions
   - Each chain has independent storage namespace
   - Enables multi-chain light clients

✅ **Direct BlockData Conversions**
   - `BlockData::from(&BeaconBlock)` - no intermediates
   - `BlockData::from(&Block)` - no intermediates
   - Deprecated `CompleteBatchBlock` intermediary type

✅ **MMRLight for Light Clients**
   - Stores only peaks + recent blocks (~4KB vs 64MB)
   - Updated with calculated peaks from verification
   - HashSet-based for O(1) block lookups

### Migration Notes

**For Full Nodes:**
```rust
// OLD (deprecated)
let batch = CompleteBatchBlock::from_beacon_block(&block);
let block_data = BlockData::from_complete_batch_block(&batch);

// NEW (preferred)
let block_data = BlockData::from(&block);
```

**For Light Clients:**
```rust
// OLD (trusted peaks)
mmr_light.update_peaks(proof.peaks.clone());

// NEW (calculated peaks)
let result = verify_batch_proof(&proof);
if result.valid {
    mmr_light.update_from_verified_proof(
        result.peaks,      // Calculated, not trusted!
        result.leaf_count,
        &blocks,
    );
}
```

**For Storage:**
```rust
// OLD (collision risk)
storage.save_state(&state)?;

// NEW (namespaced)
storage.save_state(ChainId::Beacon, &state)?;
storage.save_state(ChainId::Shard(5), &shard_state)?;
```

- Batch proof (100 blocks): ~5ms

**Memory Usage:**
- Full MMR (1M blocks): ~64MB
